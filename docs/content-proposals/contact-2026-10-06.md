## États : envoi, succès, échec

| Clé | Texte | Mel's comment |
|---|---|---|
| `status.sending` | Envoi du message en cours… | |
| `status.sending.ariaLabel` | Envoi du message en cours | |
| `success.title` | Message envoyé. | |
| `success.body` | Merci {firstName}. Votre message a bien été envoyé. Je reviendrai vers vous dans les plus brefs délais. | |
| `success.backLink` | Retour au site | |
| `error.generic.title` | Le message n'a pas pu être envoyé. | |
| `error.generic.body` | Un incident s'est produit. Veuillez réessayer dans un instant. | |
| `error.network.body` | La connexion semble interrompue. Vérifiez-la, puis réessayez. | |
| `error.rateLimit.body` | Trop de tentatives. Veuillez patienter quelques instants avant de réessayer. | |
| `error.retry` | Réessayer | |
| `error.dataKept` | Les informations saisies sont conservées dans le formulaire. | |

Remarques :
- **Succès** : la maquette affichait « Je vous réponds à {email} » ; j'ai conservé l'idée (« Je vous répondrai à l'adresse {email} ») sans délai. L'e-mail repris est celui que le visiteur vient de saisir : il n'est jamais affiché ailleurs.
- **Prénom** : `{firstName}` est le premier mot du nom saisi. Si le champ contient un seul mot ou des caractères inhabituels, prévoir un texte de repli sans prénom : `success.body.noName` = « Merci. Votre message a bien été transmis à Softn.io. Je vous répondrai à l'adresse {email}. »
- **Échec** : la maquette n'a pas d'état d'erreur ; ces textes sont nouveaux, rédigés comme les erreurs du chatbot. `error.dataKept` n'est vrai que si le formulaire conserve effectivement la saisie : à confirmer avec `nextjs-dev`, sinon à supprimer.
- **Fausse réussite du champ piège** : dans la maquette, un robot qui remplit le champ piège voit le message de succès (aucun envoi réel). Aucun texte spécifique : c'est volontaire.
